# DexLineage

Version 0.4 provides manual-corpus Analysis and knowledge-driven multi-round Migration. Every new published binding requires an executable rule whose full-APK result identifies one definite entity. General facts and application-specific compiled strategies may compose. Real application tags, service lists and manual names remain local configuration; obfuscated expected targets must not be hardcoded in matching.

- `analysis` owns discovery, current-version targets, semantic review, base-knowledge updates and publication. `migration` owns continuity within its frozen semantic target set, rule overrides, unresolved carry-forward and migrated publication. They communicate through `VersionKnowledge`, never each other's services or review models.
- `knowledge` owns schema 4 class/method identities, rule revisions, Resolution data, dependency proofs, support anchors, serialization, evidence files and mechanical revision storage. `jadx` owns APK facts, registered strategy execution, full-domain resolution execution, Java/Smali and Mapping adapters; keep JADX types inside it. `cli` owns dispatch, distribution and real-case tests.
- Discovery can produce many owners. Per-target uniqueness requires actual locator execution over the whole APK. Never restrict it to an expected owner or discovery subset. Multiple fields or locators supporting the same original class count as one entity.
- `UNIQUE` permits class-name semantic review, not automatic Rename. A support anchor may publish a unique mechanical class/method binding without Review and can be used in a subsequent run. It has no rename authority. Multiple definite candidates are `AMBIGUOUS`; unresolved competing entities are `UNKNOWN`. Aliases, confidence and Review text cannot eliminate candidates.
- Factors describe one bound field/call/assignment. Unsupported configuration fails; unavailable facts remain UNKNOWN. Preserve relevant candidates and diagnostics. Scan errors must not masquerade as no matches.
- gRPC discovery follows a resolved current-APK method identity across the full APK. Service review filters do not narrow matching. Keep every call observation, distinguish configuration uses from Descriptor construction, and group shared Proto classes into one target with all exact service/RPC/role selectors.
- Relevant unresolved construction paths block UNIQUE even when no candidate type can be identified. Record their source method and position; never manufacture a caller-as-Proto candidate. Two definite conflicting entities remain AMBIGUOUS.
- Method identity includes the full owner, original method name and signature; two methods on the same owner remain different entities. Corpus expectations are checked after execution and never restrict the matcher domain. Preserve all manual annotations while only class annotations become rename targets.
- A run consumes frozen current-APK anchors, never anchors it just produced. Missing resolved dependencies wait without fabricated NO_MATCH. Migration keeps the original source target set and uses an explicit target-base snapshot for subsequent rounds. Source-version bindings never satisfy target-version dependencies.
- Freeze APKs, complete rules and revision digests, Resolution identities, engine build identity, thresholds and base knowledge into runs. Rule changes require a new run. An override replaces the target's entire locator set; it does not add votes to an ambiguous rule.
- Keep captures separate from proposed and confirmed names. Analysis may correct a semantic name for a uniquely identified entity. Migration continues the existing name. Reviews bind the current Resolution and rule revision rather than a caller-selected descriptor.
- Analysis base knowledge belongs to the same APK. Reuse semantic IDs by current entity binding, not alias. Preserve unchanged valid entries and historical unresolved items. A failed new attempt must not erase valid base knowledge; do not silently move an existing ID to another class.
- Explicit same-APK identity references supply IDs and canonical names only after unique matching. They cannot supply a new Review, matching proof or dependency anchor. Reference-only classes need current evidence and review before entering a theme package; unrelated reference entries stay outside it.
- Conflicting new updates are rejected as a group. Updates that conflict with untouched base knowledge do not remove that base knowledge. Keep last-confirmed source for unresolved entries, without invented current bindings.
- Preserve original APKs, JADX projects and GUI sessions. Repeatable private profiles, rules, reviews, extracts and results belong under ignored `.local/`. Use ignored `.runtime/` for temporary experiments. Do not commit private analysis.
- Submission is an atomic single-writer journal with idempotent retries and explicit `supersedes`. Publish to fresh directories; use `publish --at` for historical snapshots. Fresh matching execution and saved publication replay are different proofs.
- Upgrade v0.3/v0.2/S1 packages only through explicit import commands. Reuse a prior semantic review only when its proof validates and fresh unique matching retains its binding. Inherited v0.3 claims may require explicitly supplied history packages; never search private directories to guess them. Partial Java is allowed when limitations were acknowledged.
- Use existing rule parameters and ordinary compiled strategy functions. Application-specific code is a supported scope, with the same identity, evidence, uniqueness and regression requirements as general code. Probes belong in `.runtime` and cannot be production dependencies. There is no arbitrary script/plugin runtime, model SDK, GUI/MCP or automatic graph scheduler.
- Use the committed Wrapper and locked dependencies. Ordinary test/build do not require Android SDK or APKs. Public `fixtureIntegrationTest` explicitly builds the optional `:fixture-apk` Android module at `fixtures/android` and drives installed CLI subprocesses. Keep R8 Mapping and expected identities in test assertions; never feed them to production matching. Fixture Reviews are predefined semantic test truth, not an evaluation of Agent judgment.
- Public fixture Java stays readable and self-authored. R8 performs real symbol renaming with shrinking/optimization disabled. A broken sample fails preflight; do not hide it with a skipped test, hardcoded candidates or relaxed production constraints. Generated fixtures and logs belong in build directories and may be uploaded by CI; private `.local`/`.runtime` content must never be committed or uploaded.
- Private real acceptance uses explicit local configuration, actual Agent review, fresh full-APK matching and independent JADX Mapping readback. No historical success count is a quota. Preserve the distinction between fixture regression, actual semantic review, matching re-execution and publication replay.
