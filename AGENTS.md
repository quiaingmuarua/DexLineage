# DexLineage

Version 0.3 provides single-APK Analysis and knowledge-driven Migration. Every new published binding requires an executable rule whose full-APK result identifies one definite entity. Application tags, obfuscated names, expected candidates and desired targets must not be hardcoded in production matching.

- `analysis` owns discovery, current-version targets, semantic review, base-knowledge updates and publication. `migration` owns continuity within its frozen semantic target set, rule overrides, unresolved carry-forward and migrated publication. They communicate through `VersionKnowledge`, never each other's services or review models.
- `knowledge` owns schema 3 identities, rule revisions, Resolution data, serialization, evidence files and mechanical revision storage. `jadx` owns APK facts, factor evaluation, full-domain resolution execution, Java/Smali and Mapping adapters; keep JADX types inside it. `cli` owns dispatch, distribution and real-case tests.
- Discovery can produce many owners. Per-target uniqueness requires actual locator execution over the whole APK. Never restrict it to an expected owner or discovery subset. Multiple fields or locators supporting the same original class count as one entity.
- `UNIQUE` permits semantic review, not automatic acceptance. Multiple definite candidates are `AMBIGUOUS`; unresolved competing entities are `UNKNOWN`. Aliases, confidence and Review text cannot eliminate candidates. The current Review protocol has no SELECT/EXCLUDE acceptance path.
- Factors describe one bound field/call/assignment. Unsupported configuration fails; unavailable facts remain UNKNOWN. Preserve relevant candidates and diagnostics. Scan errors must not masquerade as no matches.
- Freeze APKs, complete rules and revision digests, Resolution identities, engine build identity, thresholds and base knowledge into runs. Rule changes require a new run. An override replaces the target's entire locator set; it does not add votes to an ambiguous rule.
- Keep captures separate from proposed and confirmed names. Analysis may correct a semantic name for a uniquely identified entity. Migration continues the existing name. Reviews bind the current Resolution and rule revision rather than a caller-selected descriptor.
- Analysis base knowledge belongs to the same APK. Reuse semantic IDs by current entity binding, not alias. Preserve unchanged valid entries and historical unresolved items. A failed new attempt must not erase valid base knowledge; do not silently move an existing ID to another class.
- Conflicting new updates are rejected as a group. Updates that conflict with untouched base knowledge do not remove that base knowledge. Keep last-confirmed source for unresolved entries, without invented current bindings.
- Preserve original APKs, JADX projects and GUI sessions. Repeatable private profiles, rules, reviews, extracts and results belong under ignored `.local/`. Use ignored `.runtime/` for temporary experiments. Do not commit private analysis.
- Submission is an atomic single-writer journal with idempotent retries and explicit `supersedes`. Publish to fresh directories; use `publish --at` for historical snapshots. Fresh matching execution and saved publication replay are different proofs.
- Upgrade v0.2/S1 packages only through explicit import commands. Reuse a prior semantic review only when its proof validates and fresh unique matching retains its binding. Partial Java is allowed when limitations were acknowledged. Do not guess legacy formats or restore a second legacy execution workflow.
- Use existing rule parameters where possible. This version has no FunctionMap/custom Handler framework, arbitrary scripts, model SDK, GUI/MCP or automatic rule repair. New capabilities require a concrete task; a future Handler must return the same candidate/fact contract and cannot write Mapping.
- Use the committed Wrapper and locked dependencies. Ordinary test/build do not require Android SDK or APKs. Public `fixtureIntegrationTest` explicitly builds the independent `fixtures/android` project and drives installed CLI subprocesses. Keep R8 Mapping and expected identities in test assertions; never feed them to production matching. Fixture Reviews are predefined semantic test truth, not an evaluation of Agent judgment.
- Public fixture Java stays readable and self-authored. R8 performs real symbol renaming with shrinking/optimization disabled. A broken sample fails preflight; do not hide it with a skipped test, hardcoded candidates or relaxed production constraints. Generated fixtures and logs belong in build directories and may be uploaded by CI; private `.local`/`.runtime` content must never be committed or uploaded.
- Private real acceptance uses explicit local configuration, actual Agent review, fresh full-APK matching and independent JADX Mapping readback. No historical success count is a quota. Preserve the distinction between fixture regression, actual semantic review, matching re-execution and publication replay.
